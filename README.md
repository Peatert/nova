# Nova

Учебный проект необанка: API, веб-сайт, приложение для ПК и Android, админка сотрудников и панель владельца.
**Не является кредитной организацией.** Все данные в базе сгенерированы, люди и карты вымышлены.

## Стек

- .NET 10 (LTS), C#
- ASP.NET Core Minimal API
- EF Core 10 + PostgreSQL 17 (Npgsql)
- xUnit
- Docker Compose
- Позже: .NET MAUI (приложение), Blazor (админка)

## Структура

```
Nova.sln
├─ src/
│  ├─ Nova.Domain          сущности, бизнес-правила, роли и права, алгоритм Луна (без зависимостей)
│  ├─ Nova.Infrastructure  EF Core, миграции, шифрование полей (AES-GCM), хеширование паролей (PBKDF2)
│  ├─ Nova.Api             HTTP API: авторизация (JWT, 2FA), счета, переводы, служебные эндпоинты
│  ├─ Nova.Contracts       DTO запросов и ответов API — общие для API и приложения
│  ├─ Nova.App             приложение .NET MAUI: Android + Windows
│  ├─ Nova.Admin           консоль владельца и сотрудников (Blazor, серверный рендеринг)
│  └─ Nova.Seeder          генератор тестовых данных: 200 тыс. клиентов, 5 млн проводок
├─ tests/
│  ├─ Nova.Tests              unit-тесты (без БД, секунды)
│  └─ Nova.IntegrationTests   API + настоящий PostgreSQL в Docker (Testcontainers)
├─ db/
│  └─ benchmarks.sql       замеры запросов: с индексами и без, партиции
└─ docker-compose.yml      PostgreSQL (+ pgAdmin по профилю tools)
```

## Ключевые решения

| Решение | Зачем |
|---|---|
| `numeric(19,4)` для всех денег | Никаких ошибок округления float |
| Двойная запись (`ledger_entries`) | Каждый перевод — дебет + кредит, баланс сверяется по проводкам |
| `idempotency_key` в переводах | Повторный запрос не спишет деньги дважды |
| `xmin` как row version | Оптимистическая блокировка счёта при параллельных переводах |
| CHECK `balance >= -credit_limit` | Уход в минус невозможен даже при баге в коде |
| Схемы `clients / accounts / transactions / staff / audit` | Права в БД выдаются на домен целиком |
| Права, а не роли, в проверках | Роль — набор прав, меняется без правки кода |
| Аудит-лог с цепочкой SHA-256 | Удаление или правка записи обнаруживается автоматически |
| Владелец без права `rates.approve` | Принцип четырёх глаз: ставки владельца подтверждает бухгалтерия |
| `ledger_entries` партиционирована по месяцам | Запрос за месяц читает одну партицию, старые месяцы можно архивировать целиком |
| Номер карты и паспорт — AES-256-GCM | В БД только шифротекст; подмена шифротекста обнаруживается |
| Пароли — PBKDF2-SHA256, 100 000 итераций, соль | Утечка базы не раскрывает пароли |
| Генерация через бинарный `COPY` | 7,5 млн строк за минуты, а не за часы через ORM |
| JWT на 15 минут + refresh-токен с ротацией | Украденный access-токен быстро протухает; повторное использование refresh гасит всю сессию |
| Refresh-токен хранится только как SHA-256 | Утечка таблицы `auth.refresh_tokens` не даёт войти |
| 2FA (TOTP, RFC 6238) своей реализацией | Работает с Google Authenticator / Яндекс Ключ; один код нельзя использовать дважды |
| Владелец без 2FA получает токен без прав | Самая привилегированная роль физически не работает на одном пароле |
| 5 неверных паролей → блокировка на 15 минут | Защита от подбора; плюс лимит 10 запросов в минуту к `/api/auth` с IP |
| Одинаковый ответ и время для «нет пользователя» и «неверный пароль» | По ответу нельзя узнать, зарегистрирован ли телефон |
| Каждый вход, ошибка и блокировка — в аудит-лог в одной транзакции с действием | Действие без записи в журнале невозможно |
| Перевод: `SELECT … FOR UPDATE` обоих счетов до проверки баланса | 100 параллельных переводов с одного счёта не уводят его в минус (есть тест) |
| Блокировки счетов всегда по возрастанию id | Встречные переводы A→B и B→A не дедлочатся (есть тест) |
| `Idempotency-Key` обязателен для перевода | Повтор запроса после обрыва сети не спишет деньги дважды, даже если повторы пришли одновременно |
| Перевод по id — только между своими счетами, чужим — только по телефону | id счёта не работает как реквизит, перебором ничего не узнать |
| Переводы клиентов не пишутся в аудит-лог | Книга проводок уже неизменяема; цепочка аудита с глобальной блокировкой стала бы узким местом. Аудит — для действий сотрудников и безопасности |
| Выписка только за период (по умолчанию 90 дней) + курсор | Отсечение партиций работает на каждом запросе выписки |
| Integration-тесты на настоящем PostgreSQL (Testcontainers) | Блокировки, партиции и уникальные индексы проверяются по-настоящему, а не на моках |

## Запуск

Нужно: [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) и Docker Desktop.

```powershell
# 1. Инструмент миграций (один раз)
dotnet tool install --global dotnet-ef

# 2. База данных
copy .env.example .env
docker compose up -d

# 3. Тесты (integration-тестам нужен запущенный Docker)
dotnet test

# 4. Тестовые данные (миграции применятся автоматически). Занимает несколько минут.
dotnet run --project src/Nova.Seeder -c Release

# 5. API
dotnet run --project src/Nova.Api
```

Быстрая проверка генератора на малом объёме:
`dotnet run --project src/Nova.Seeder -c Release -- --clients 2000 --transfers 20000 --reset`

Тестовые учётные записи (только для локальной разработки):

| Кто | Логин | Пароль |
|---|---|---|
| Любой клиент | телефон `+7999XXXXXXX`, например `+79990000000` | `Nova-client-2026!` |
| Сотрудники | `owner`, `operator`, `support`, `credit`, `risk`, `accountant`, `auditor`, `sysadmin` | `Nova-staff-2026!` |

## API

Все сценарии с готовыми запросами — в `src/Nova.Api/Nova.Api.http` (открыть в Visual Studio, «Send request»).

| Метод | Путь | Доступ | Что делает |
|---|---|---|---|
| POST | `/api/auth/client/register` | все | Регистрация: клиент + дебетовый счёт + карта |
| POST | `/api/auth/client/login` | все | Вход по телефону и паролю |
| POST | `/api/auth/staff/login` | все | Вход сотрудника по логину |
| POST | `/api/auth/2fa` | MFA-токен | Второй фактор: код из приложения |
| POST | `/api/auth/refresh` | refresh-токен | Новая пара токенов, старый refresh отзывается |
| POST | `/api/auth/logout` | refresh-токен | Отзыв всей сессии |
| GET | `/api/me` | вошедший | Профиль, роль, права |
| GET | `/api/accounts` | клиент | Свои счета, балансы, карты |
| GET | `/api/accounts/{id}/statement?from&to&before&limit` | клиент | Выписка за период, пагинация курсором |
| GET | `/api/transfers/recipient?phone=` | клиент | Имя получателя по телефону («Алексей С.») |
| POST | `/api/transfers` + заголовок `Idempotency-Key` | клиент | Перевод по телефону или между своими счетами |
| GET | `/api/transfers/{id}` | клиент | Детали своего перевода |
| POST | `/api/me/2fa/setup`, `/confirm` | вошедший | Включение 2FA: QR-код и подтверждение |
| GET | `/api/system/stats` | `reports.read` | Объём данных |
| GET | `/api/system/reconcile` | `reports.read` | Сверка: баланс = сумма проводок, дебет = кредит |
| GET | `/api/system/partitions` | `reports.read` | Партиции книги проводок |
| GET | `/api/system/roles` | `staff.manage` | Матрица ролей и прав |
| GET | `/api/system/audit/verify` | `audit.read` | Целостность цепочки аудита |
| GET | `/api/system/audit/recent` | `audit.read` | Последние события аудита |
| GET | `/health` | все | Состояние API и БД |
| GET | `/openapi/v1.json` | все (dev) | OpenAPI-спецификация |

pgAdmin: `docker compose --profile tools up -d` → http://localhost:5050 (admin@nova.local / admin).

## Приложение (Android + Windows)

.NET MAUI, MVVM (CommunityToolkit.Mvvm), один код на обе платформы.

| Экран | Что умеет |
|---|---|
| Вход | Телефон + пароль, второй шаг с кодом 2FA, запоминание сессии |
| Главная | «Все деньги», счета и карты, скрытие балансов, последние операции, обновление свайпом |
| Перевод | По номеру телефона, показ получателя «Имя Ф.», экран успеха с анимацией |
| Выписка | 90 дней, подгрузка при прокрутке (курсор API) |
| Профиль | Статус защиты сессии, выход с отзывом сессии на сервере |

- Живой фон: звёзды, пульсирующая сверхновая и метеоры рисуются кодом (`GraphicsView`), без картинок.
- Токены — в `SecureStorage` (Android Keystore) и DPAPI на Windows. Пароль на устройстве не хранится.
- Access-токен живёт 15 минут, приложение тихо обновляет его по refresh и повторяет запрос.
- `Idempotency-Key` создаётся на «черновик» перевода: повторное нажатие после обрыва связи не спишет деньги дважды.

Запуск на Android-телефоне по USB (API остаётся на ПК):

```powershell
& "C:\Program Files (x86)\Android\android-sdk\platform-tools\adb.exe" reverse tcp:5080 tcp:5080
```

Команда пробрасывает `127.0.0.1:5080` телефона на ПК — Wi-Fi и брандмауэр не нужны. Повторять после каждого переподключения телефона.

## Консоль владельца

`dotnet run --project src/Nova.Admin` → http://localhost:5090

| Раздел | Право | Что показывает |
|---|---|---|
| Обзор | `bank.dashboard` | Клиенты, средства, долг по кредиткам, переводы сегодня, график за 14 дней, безопасность |
| Клиенты | `clients.read` | Поиск по телефону или ФИО; телефон маскируется без права `clients.personal_data` |
| Сверка | `reports.read` | Баланс = сумма проводок по всем счетам, дебет = кредит, партиции |
| Аудит | `audit.read` | Проверка цепочки SHA-256 и журнал событий с фильтром |

- Вход: логин + пароль + код 2FA. Владелец без включённой 2FA в консоль не попадает.
- Cookie `HttpOnly` + `SameSite=Strict`, сессия 30 минут, защита от open redirect, общая блокировка после 5 ошибок.
- Аудитор (`auditor`) видит только аудит: обзор и клиенты для него закрыты — проверка разделения прав.

Демо-история для клиента `+79990000000` (около 200 операций за 90 дней, через настоящий `TransferService`):

```powershell
dotnet run --project src/Nova.Seeder -c Release -- --demo
```

## Данные

| Таблица | Строк |
|---|---|
| Клиенты | 200 001 (включая технического) |
| Счета (дебетовые, накопительные, кредитные) | ~350 000 |
| Карты | ~250 000 |
| Переводы | 2 500 000 |
| Проводки | 5 000 000 |

История за 18 месяцев: зарплаты, покупки, переводы по номеру телефона, пополнение и вывод с накопительного,
погашение кредитки. Дебетовый счёт никогда не уходит в минус, кредитный — не дальше лимита.
После генерации выполняется сверка: баланс каждого счёта равен сумме его проводок.

## Производительность

Замеры: `db/benchmarks.sql` (инструкция по запуску — в начале файла).
Стенд: PostgreSQL 17 в Docker Desktop (WSL 2), Windows, база 2,2 ГБ, 5 млн проводок в 19 месячных партициях по ~280 тыс. строк.
Время — `Execution Time` из `EXPLAIN ANALYZE`, прогретый кэш.

| Запрос | С индексом / отсечением партиций | Без | Ускорение |
|---|---|---|---|
| Выписка: последние 50 операций счёта | **0,12 мс** (Index Scan) | 90,5 мс (Parallel Seq Scan) | ~750× |
| Поиск клиента по телефону | **0,025 мс** (уникальный индекс) | 13,2 мс (Seq Scan) | ~530× |
| Оборот банка за месяц | **20,4 мс** (читается 1 партиция) | 308,7 мс (читаются все) | ~15× |
| Обороты одного счёта за месяц | **0,056 мс** (1 партиция + индекс) | — | — |

Выводы:

- Без индекса `(account_id, created_at DESC)` выписка — это полный проход по 5 млн строк. С индексом PostgreSQL
  берёт готовые отсортированные строки из каждой партиции и сливает их (`Merge Append`), без сортировки.
- Фильтр по дате включает отсечение партиций: в плане запроса за месяц видна одна партиция `ledger_entries_2026_09`
  из 49. Отчёты за период стоят столько, сколько данных в периоде, а не во всей истории.
- Обратная сторона: в выписке без фильтра по дате планировщик перебирает все 49 партиций, и планирование
  (~0,6–1 мс) дольше самого выполнения (0,12 мс). Поэтому в API выписка будет запрашиваться за период
  (по умолчанию 90 дней), а пустые партиции 2024 года можно удалить.
